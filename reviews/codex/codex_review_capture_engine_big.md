## Product Challenges

I am not challenging the locked product decisions: capture vs gold, offense default as CONVEX, 13-week capture / 8-week trend, and relative-to-universe cutoffs are implemented consistently enough for this phase.

I do challenge the wording around prediction and ownership language. "Modelled probability", "reliably beats", "leading indicator", and "better miners to own" are too strong for a descriptive, survivor-only, no-walk-forward engine. This is not a request to reopen the product decisions; it is a request to make the UI and help copy match those decisions.

## Prioritized Fix List

1. Close the source-spine invariant first: behavior build must require live `dial_meta`, and serve must mark missing/malformed behavior `source_spine` as `STALE` when live dial meta has a pointer.
2. Fix the trend label math: require raw delta threshold in addition to shrunk delta, and replace small-N z-tests with exact tests or higher floors.
3. Validate behavior frame schema/hash metadata in serve before rendering any behavior panel data.
4. Add `alpha_anchor_n` from finite alpha observations and use it for alpha trend eligibility.
5. Expand dial provenance with per-equity file hashes.
6. Tighten user-facing honesty: remove predictive wording, show capture effective N, and show trend anchor/FDR basis.
7. Preserve behavior frame failure causes instead of collapsing them to `CORRUPT`.
8. Sweep the low/nit items: dynamic trend horizon copy, trend label NaN guard, cutoff warning tests, serve guardrail clarity, shared missing-value helpers, and exact tie-policy tests.
