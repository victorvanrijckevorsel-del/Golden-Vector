## Verified first-hand (the load-bearing parts)
- **Architecture is right.** `portfolio/` is a clean package: `pipeline` computes + persists immutable artifacts; `reader` resolves them through `resolve_current_model_artifact_path` (manifest, immutable paths); `serve/portfolio_page.py` only **reads** + renders. No coupling to `hedge/report.py` markdown. (`reader.py:31-78`, `portfolio_page.py:40-50`)
- ⭐ **No double pence-adjustment** — the exact bug I went looking for. The snapshot's `share_price_local` is already pence-corrected at ingestion; `pipeline._value_lot` passes `feed_currency=None` to `value_line`, so `price_unit_adjustment` keys off `lot.buy_currency` (`"GBP"`, not `"GBp"`) → scale 1.0, no second ÷100. It still records the snapshot's `price_scale_factor`/`minor_unit_adjusted` as provenance. Correct and honest. (`pipeline.py:248-281`)
- **Shared pence helper, no duplication.** The `GBp` logic now lives once in `normalize/price_units.py` (case-sensitive `GBp`≠`GBP`), used by **both** `ingestion/standardize.py` and `portfolio/valuation.py`. Exactly the v4 §1b requirement. (`price_units.py`)
- **P&L math is correct + honestly named.** `cost_local = shares×buy_price`; `value_local = shares×current_major_price`; `pnl_local`/`pnl_pct_local` local-primary; USD totals at **current** FX with `*_at_current_fx` names (FX-at-buy-date is deferred, and the naming says so). Grouping blends to `avg_cost_local = Σcost/Σshares`. (`pipeline.py:259-282`, `_positions_frame`)
- **Manual store is safe.** Atomic writes (`atomic_write_text`), stable UUID ids, **validate-before-write** (a bad input never touches the file), store `schema_version` checked on load, reuses `normalize_ticker`/`clean_string`. Validation: active-universe ticker (else "add to universe first"), shares>0, price>0, currency in `SUPPORTED_CURRENCIES`, non-future date, note length. (`manual_store.py`)
- **Write path is clean.** `/portfolio/lots*` is POST-only, **gated on `portfolio.enabled`** (403 otherwise), validates → writes store → runs `build_portfolio_artifacts` (reads persisted snapshot, **no Yahoo call**) → **redirects** (`?saved`); validation errors re-render the page with a friendly message at **400, not a 500**. (`workspace.py` portfolio block)
- **Privacy is thorough.** `portfolio.enabled` defaults **False**; store under gitignored `data/manual/portfolio/`, artifacts under gitignored `data/output/portfolio/`, plus explicit `ibkr*.csv`/`*portfolio*.csv` ignores; `run_workspace_server` **refuses a non-loopback bind** when portfolio is enabled (`_is_loopback_host`); **both** `/hedge-readiness` (HTML **and** `.md`) are now gated behind `portfolio.enabled`, closing the pre-existing holdings-leak endpoint. (`workspace.py:112-127,609,652`, `.gitignore`, `paths.py`)

(`reader.py`, `workspace.py:609`)

(`model_state.py` diff)

## Findings (all minor — none block)
**F1 — NIT: `position_weight_pct` / `pnl_pct_local` store a *fraction* (0.22), but the names say "pct".** They render correctly because the page's `_fmt_percent` multiplies by 100 ("22.0%"), so this is cosmetic — but an artifact *consumer* (a future milestone or the reconciliation CSV) could read `0.22` and treat it as 0.22%. Consider renaming to `*_fraction`, or store ×100, for self-describing artifacts.

**F2 — NOTE (intended behavior change worth recording): `/hedge-readiness` now returns 403 by default.** Gating both the HTML page and the `.md` download behind `portfolio.enabled` is the right privacy call (the report carries holdings), but anyone who used hedge-readiness before must now set `portfolio.enabled: true`. Worth a one-line note in the README/changelog so it isn't a surprise.

**F3 — MINOR: a portfolio lot edit re-publishes the *global* model-state manifest** (+ its retention snapshot) via `build_portfolio_artifacts(... publish_model_state=True)`. It's a safe from-disk rebuild, but it's a non-obvious side effect of a UI edit. Confirm that's intended (vs. writing only the portfolio artifacts and leaving the manifest publish to refresh). Fine functionally; just make it a conscious choice.

**F4 — MINOR (known M1 limitation, consistent with the plan): single currency per ticker.** `validate_lot_input` forces `buy_currency == info.currency`, so a name held on two exchanges in different currencies (e.g. Celsius CLA.AX/AUD vs a London line) can only be recorded in the universe ticker's currency. Acceptable — broker-line/dual-listing handling is explicitly M2+ — but worth a hint in the UI ("M1 records buys in {ticker}'s currency") so it isn't confusing.

F1–F4 are nits/notes — fix F1 if cheap, record F2, confirm F3, add the F4 hint.
