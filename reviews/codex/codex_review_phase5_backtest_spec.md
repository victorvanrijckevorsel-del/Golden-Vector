# Codex Review - Phase 5 Behaviour Backtest Spec

Scope: review of `reviews/codex/claude_phase5_behaviour_backtest_spec.md` as a pre-registration plan, not an implementation. I did not edit the spec or product code.

Process: read the spec, companion prompt, `.claude/skills/predictive-models/SKILL.md`, `behavior_engine.py`, and the reusable Lab infra (`walk_forward`, `evaluation`, `forward_returns`, `ledger`, `validation`, `scorecard`). Five dimension agents reviewed the plan, then three skeptic agents tried to refute the merged candidates. The table below keeps the findings that survived that pass, with duplicates merged.

Final verdict: **NEEDS CHANGES** before freeze.

## Section 11 Answers

| Question | Recommendation |
|---|---|
| Target IR 0.3 / transfer 0.5 | Co-sign the numbers as a reasonable gross, survivor-only bar for a roughly 60-name universe. Do not freeze until the required IC is mechanically derived from a pinned pre-window and made a binding gate. |
| NW lag | Lag-1 is acceptable only if folds are single-as-of observations spaced by the horizon: `test_weeks=1`, `step_weeks=H`, plus an explicit cross-fold label-overlap assertion. For multi-week test blocks, scale HAC lag to actual overlap or use a block bootstrap. |
| DSR report vs gate | Reported-not-gated is acceptable for "does the rank predict?" claims, but DSR failure must cap performance wording. Remove "DSR > 0 is a floor" or explicitly make it a verdict cap. Use a phase-wide ledger denominator covering all Phase 5 registered variants, including robustness and reruns. |
| Fold parameters | Use `min_train_weeks=260`, `test_weeks=1`, `step_weeks=H`, anchored on the 2010+ weekly spine. Local count on current `dial_episodes_latest.parquet`: about 74 folds for H=8 and 45 folds for H=13. Stamp expected counts in meta before compute. |

## Blocking List Before Freeze

1. Freeze fold geometry and add cross-fold label-overlap assertions.
2. Fix or remove constant/undefined baselines and pin all baseline orientations.
3. Make the N_eff-derived required IC/IR floor a binding gate and freeze its derivation.
4. Extend ledger semantics for Phase 5 family/role/trial counts and resolve DSR gate-vs-report wording.
5. Pin E4 grain and verdict precedence, especially the shipped NULL wording.
6. Define E2's forward asymmetry label and side-coverage floors.
7. Specify Ledoit-Wolf/N_eff implementation details or dependency plan.

Once those are resolved, the plan is close to freeze-worthy.
